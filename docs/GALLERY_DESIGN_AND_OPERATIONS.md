# ギャラリー設計と公開運用（2026-10-03）

## 合意したUI/UX

2人のレビュー担当で「見つける・遊ぶ・持ち帰る」に絞ると合意。管理用の開催地→開催日→作品の階層を廃止し、最新の公開作品一覧を入口にする。作品名検索と3ジャンルの絞り込み、30件ごとのページ切替。サムネイル未登録のためジャンル素材をイメージとして明記する。Canvas作品が空白になる静的iframeプレビューは使用しない。

作品詳細にはタイトル、実際のゲーム、具体的な公開期限（日本時間）、ZIP保存を配置。通信失敗と公開終了を区別し、存在しない作品は削除済みと断言しない。ダウンロード失敗時に不完全なZIPを渡さない。

## 登録

ワークショップの「発表」でフォルダを公開する。開催地・開催日・セッションの事前登録は不要。ジャンルを添付しsession_idはNULL。登録前に誰でも閲覧・DLできることと2ヶ月後の削除を表示する。管理者ページとビルド入口は削除。

## 期限・削除

- 新しいworkshop/作品の uploaded_at と expires_at はサーバーが決定する。
- 期限はUTC基準で公開時刻から2暦月。同日がない月は月末。
- 期限になった作品はDBの公開読み取り対象から除外する。開いている作品ページも終了状態へ切り替える。
- Supabase Cronが毎時17分にEdge Functionを呼ぶ。期限切れのworkshop/作品だけStorage APIでファイルを削除し、その後DB行を削除する。
- Storage失敗時はDB行を残す。DB失敗もエラーにし、次回再試行する。1000件を超えるファイルもページングし、100件ずつ削除する。
- game-filesは既存の公開バケットを使用。ギャラリー公開は期限時刻に終了するが、直接のStorage URLは定期削除完了まで取得できる。通常は次の毎時実行時に削除、失敗・サービス停止時は遅延する。既にダウンロードしたコピーは削除されない。
- 管理画面で以前登録されたworkshop/以外の作品は今回の自動削除対象にしない。既存データは移行で消さない。

権限の変更は、匿名・ログイン済み利用者が新しいworkshop/ファイルと公開作品だけを追加できるようにすること。更新・削除のブラウザー権限は付けず、旧認証ユーザーのgames全操作権限とStorage全操作権限は撤去。削除関数はservice_roleで認証した内部呼出しだけを許可する。
